Login v1 — Session Token

/login Business · Provider

Acquire a session-based authorization token. Session token expires after 20 minutes and refreshes on every API call.

Rate Limit: QUOTA_EXCEEDED error occurs when you exceed login requests per second. Use the login API once and reuse the session token. Retry after 1-2 seconds.

Request

FieldTypeRequiredDescription
emailstringYesEmail credential
passwordstringYesPassword
Example Request & Response 
POST /login
Content-Type: application/json

{
    "email": "sandbox_dev@gmail.com",
    "password": "password"
}
200 OK
{
    "success": true,
    "results": {
        "apiKey": "fb77c9653bf5e736d191b46bbfed7c2bd",
        "clientId": "SANDBOX_DEV",
        "sessionToken": "b45e2fb77c9653bf5e736d19e1fd18ebbffd0f6d3dd25af118e5eb38851bf4d"
    }
}

Response Fields

FieldDescription
apiKeyHash used as query parameter in subsequent API calls
clientIdYour client reference ID
sessionTokenUse as Auth-Token header. Expires after 20 minutes.
Error Responses
401 "EMAIL_NOT_FOUND" — Invalid email
401 "INVALID_PASSWORD" — Wrong password
401 "QUOTA_EXCEEDED" — Too many login requests

Login v2 — JWT Auth

/loginV2 Business · Provider

JWT-based authentication. Returns access token (20 min) and refresh token (30 days). Use /refreshToken to renew.

Using v2 tokens: Set header x-access-token: Bearer {accessToken} instead of Auth-Token. No apiKey query param needed.

Request

FieldTypeRequiredDescription
emailstringYesEmail credential
passwordstringYesPassword
Example Response 
200 OK
{
    "success": true,
    "results": {
        "accessTokenExpiresAt": 1650941635051,
        "refreshTokenExpiresAt": 1653532435052,
        "accessToken": "eyJhbGciOiJIUzI1NiIs...",
        "refreshToken": "eyJhbGciOiJIUzI1NiIs..."
    }
}

Auth Header Comparison

VersionHeaderQuery Param
v1Auth-Token: {sessionToken}apiKey={apiKey}
